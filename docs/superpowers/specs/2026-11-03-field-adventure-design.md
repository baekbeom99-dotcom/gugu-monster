## 0. 꼭 먼저 짚을 점 — 그림·이름은 우리 것으로

"파이어레드 스타일"은 **장르와 손맛**(위에서 내려다보는 픽셀 필드, 풀숲에서 갑자기 만나는 전투, 아래쪽 기술 버튼, 공을 던져 잡기, 도감)을 따라 하는 것으로 정한다. 다음은 **쓰지 않는다**.

- 포켓몬 이름·모습, 몬스터볼·도감 디자인, 원작 지도·음악·글꼴·화면 틀을 그대로 베끼기
- '포켓몬', '몬스터볼', '파이어레드' 같은 이름을 화면·앱 이름·저장소 이름에 쓰기

이 앱은 공개 주소(GitHub Pages)에 올라가므로 상표·저작권 문제를 피해야 한다. 그래서 다음처럼 바꿔 부른다.

| 원작 느낌 | 이 앱에서 |
|---|---|
| 포켓몬 | **구구몬** (테스트판은 지금 있는 몬스터 8종만, 6-1) |
| 몬스터볼 | **캡슐** (둥근 가챠 캡슐: 위 투명 하늘색·아래 노랑·가운데 별 스티커. 빨강·흰 공 디자인은 쓰지 않음) |
| 도감 | **구구몬 도감** (지금 도감 화면을 넓혀서) |
| 기술 | 구구몬마다 우리가 지은 기술 이름 (예: 새싹몬 "잎사귀 톡") |

**필드 그림의 선**: "그 시절 휴대용 게임기 RPG 느낌"까지 따라간다 — 밝고 부드러운 색, 16×16 타일, 위에서 비스듬히 내려다보는 시점. 초원은 연두 풀밭·흙길·둥근 나무·작은 집, 물가는 파란 물·모래톱·나무다리·수초, 사막은 모래색 땅·바위·선인장·마른 덤불. **원작 마을 배치를 본뜨거나, 원작 타일 그림·색을 그대로 옮겨 그리지는 않는다.** 색과 타일은 우리가 새로 고르고 그린다.

## 1. 무엇을 그대로 쓰고 무엇을 새로 만드나

### 그대로 쓰는 것 (출제 엔진)
| 모듈 | 쓰임 |
|---|---|
| `domain/facts.ts` | 구구단 사실 목록 |
| `domain/mastery.ts` | 상자(0~5)·복습 날짜·빠른 정답 기준 |
| `domain/scheduler.ts` | 다음에 낼 문제 고르기 (`planExploration`, 복습 슬롯, `insertRetry`) |
| `domain/questionGen.ts` | 문제 모양·오답 보기 만들기 |
| `domain/progress.ts` `recordAnswer` | 답 기록(숙련도·별·오답 극복) |
| `components/HintPanel` | 틀렸을 때 힌트 |

### 출제 쪽에서 조금 고칠 것
1. **보기 3개**: 지금은 `CHOICE_COUNT = 4`로 고정. `generateQuestion(rng, fact, type, choiceCount = 4)`처럼 개수를 받게 해서 기존 화면은 4개, 필드 전투는 3개로 쓴다. (기존 테스트는 그대로 통과해야 한다)
2. **3지선다는 찍어도 맞을 확률이 33% (확정)**: 그냥 두면 찍어서 상자가 5까지 오를 수 있으므로 다음처럼 막는다.
   - 필드 전투의 정답은 **상자 3까지만 올린다**(4·5는 퀴즈 모험에서 숫자를 직접 입력하거나 빠르게 맞혀서). `AnswerInput`에 `source: 'field'`를 더하고 `applyAnswer`에 상한을 넘긴다.
   - 그래서 **단 배지(숙련도 마스터)와 12·13단 열기는 퀴즈 모험에서만** 얻는다. 필드에서 많이 풀면 그 문제가 '익히는 중'까지 빨리 올라가서 퀴즈 모험이 쉬워진다.
3. **문제 모양 제한 (확정)**: 곱셈(`product`, 3×4=?)과 빈칸(`missingFirst` □×4=12, `missingSecond` 3×□=12)만 낸다. `commutative`·`sequence`, 셈 문제(덧셈·뺄셈)는 필드에서 내지 않는다. 다른 문제 종류는 나중에 추가한다.
4. **문제 단위**: 탐험 9문제 계획 대신, 전투가 끝날 때까지 필요한 만큼 이어 받는다. 이미 있는 `needsMoreQuestions`·`extendPlan` 방식을 그대로 쓴다.

- 야생 전투(실시간 HP 회복·도망 타이머·캡슐 던지기)
- 구구몬 종·레벨·경험치·진화, 동행 선택
- 픽셀 그림(캐릭터·타일·구구몬), 전환 효과

## 2. 앱 구조 — 타이틀 화면에서 두 모험 고르기 (확정)

같은 저장소·같은 앱 안에서, 처음 화면을 **타이틀 화면**으로 바꾸고 두 가지 중 고른다.

| 버튼 | 들어가면 |
|---|---|
| **퀴즈 모험** | 지금 앱 그대로 (나의 펫·탐험·상점·기록·도감 탭). 처음이면 지금처럼 알 고르기 → 부화 |
| **필드 모험** | 이번에 새로 만드는 것 (첫 구구몬 고르기 → 필드 → 야생 전투) |

- 출제 엔진과 학습 기록(`learning`)은 **두 모험이 함께 쓴다**. 필드에서 푼 문제도 퀴즈 모험의 기록 화면·숙련도에 그대로 쌓인다.
- 저장 키는 지금 것(`gugu-monster:save`) 그대로. 저장 데이터에 `field` 항목만 더한다(7절).
- 별·펫 친밀도 (확정): 필드 전투에서 맞힌 문제도 지금 탐험처럼 별과 펫 친밀도를 준다(별은 퀴즈 모험 상점에서 쓴다). 펫이 아직 알이면 친밀도는 건너뛴다.

### 2-1. 타이틀 화면
- 주소 `#/`. 지금은 `/` → `/pet`으로 바로 넘어가는데, 이것을 타이틀 화면으로 바꾼다. 알 고르기 확인(`OnboardingGuard`)은 퀴즈 모험 쪽 주소에만 남긴다.
- 화면: 앱 이름(픽셀 글씨 느낌), 뒤에 필드 풍경과 구구몬이 천천히 걷는 그림, 큰 버튼 두 개(세로로 쌓아 375px에서 엄지로 누르기 쉽게).
- 퀴즈 모험 → `#/pet`, 필드 모험 → `#/field`.
- 두 모험 모두 위쪽에 **[처음 화면]** 버튼을 둔다. 퀴즈 모험은 `TopBar`에, 필드 모험은 필드 메뉴에.
- 홈 화면에 깔아 둔 앱(PWA)을 켜면 타이틀 화면부터 나온다. 예전에 저장해 둔 `#/pet` 같은 주소는 그대로 그 화면으로 열린다.
- 새 버전 자동 새로고침(`autoUpdate.ts`)은 타이틀 화면에서 일어나도 괜찮다(바쁜 화면 목록에 넣지 않음).
- 도감 이름이 겹치지 않게: 퀴즈 모험의 `#/dex`는 지금처럼 **펫 도감**, 필드 모험은 **구구몬 도감**(`#/field/dex`).

## 3. 화면 흐름

```
타이틀 화면 ─┬─ [퀴즈 모험] → 지금 앱 (나의 펫 탭부터)
             └─ [필드 모험] → (처음이면) 첫 구구몬 고르기 3마리 중 1
                   → 초원 ⇄ 물가 / 초원 ⇄ 사막 (지도 끝 출구 → 불러오기 화면 → 다른 필드)
                   → 필드 ──(풀숲 걸음마다 만남 확률)──→ 전환 효과 → 야생 전투
                        ↑                                         │
                        └── 잡음/도망감/그만두기 → 결과 짧게 ←─────┘
                   필드 메뉴(오른쪽 위): 구구몬 도감 · 동행 바꾸기 · 처음 화면
```

화면은 휴대폰 세로(375px) 기준.
- **필드**: 위쪽 약 60%는 지도, 아래쪽 40%는 터치패드(왼쪽 십자 패드, 오른쪽 A·B 버튼)
- **전투**: 위쪽은 야생 구구몬(오른쪽 위)과 내 구구몬(왼쪽 아래, 뒷모습)·HP 바, 가운데는 문제 말풍선, 아래쪽은 기술 버튼 3개(세로로 쌓은 큰 버튼)

## 4. 필드

### 4-1. 지도
- 16×16 픽셀 타일을 화면에 맞게 정수 배율로 키운다(375px 폭이면 ×3 정도, 가로 약 8칸 보임). 픽셀이 흐려지지 않게 `image-rendering: pixelated`.
- **필드 3곳 (확정)**. 필드마다 지도 1장, **넓지 않게 약 20×20칸**(휴대폰 화면 3개 정도, 끝에서 끝까지 걸어서 15초 안쪽).
- **필드끼리 난이도 차이는 없다 (확정)**. 쉬운 단·어려운 단을 필드마다 **섞어** 두어, 어느 필드에 가도 구구단을 고루 연습한다. 배수 관계로 묶어 두 단을 함께 익히기 좋게 했다(2·4·8단, 3·6·9단). 이렇게 나누면 2~9단과 12단이 모두 한 필드에 한 번씩 들어간다.
  | 필드 | 단 | 나오는 몬스터 (테스트판) | 모습 |
  |---|---|---|---|
  | **초원** | 2·4·8단 | 새싹몬·방울무몬·왕관몬 | 연두 풀밭, 흙길, 둥근 나무, 꽃, 작은 집 |
  | **물가** | 3·6·9단 | 젤리몬·안테나몬·뿔뿔몬 | 연못·냇물(막힘), 모래톱, 나무다리, 물가 풀숲 |
  | **사막** | 5·7·12단 | 삼눈블록몬·외뿔공룡몬 | 모래색 땅, 바위·선인장(막힘), 마른 덤불 풀숲 |
- 야생 레벨은 필드와 상관없이 **Lv 3~6 중 무작위**(레전드는 20).
- **필드 잇기**: 초원이 가운데. 초원 왼쪽 끝 길 → 물가, 오른쪽 끝 길 → 사막. 출구 칸에 들어서면 불러오기 화면(4-6) 뒤 다음 필드의 입구에 선다. 처음 시작은 초원.
- **세 필드 모두 처음부터 갈 수 있다.** 사막의 12단 문제는 **퀴즈 모험에서 12·13단이 열린 뒤에만** 섞인다(지금 출제 엔진의 해금 규칙 그대로). 열리기 전 사막은 5·7단만 나온다.
- 타일 종류(필드마다 그림은 다르고 하는 일은 같다): 길, 풀숲(만남), 막힘(나무·물·바위·선인장·울타리), 꾸밈(꽃·조개껍데기·마른 풀), 표지판(글 보기), 출구.
- **문제 고르기**: 출제 엔진(`scheduler`)이 아이가 약한 문제를 고르되, **그 필드의 세 단에서만** 고른다. 세 단이 한 전투 안에서도 섞여 나온다(예: 물가 → 3×7, 6×4, 9×8 …). 세 단 사이의 비율은 출제 엔진의 약점 가중치(단 계수·숙련도 상자)를 그대로 쓴다.
  - 예외: 지금의 **오답 복습 슬롯**(다른 단에서 틀렸던 문제)은 필드와 상관없이 끼워 넣는다 — 틀린 문제를 다시 보는 것이 학습에 더 중요하므로. ⚠️ 추천안
  - 만난 몬스터의 몸 색은 그 필드 세 단 중 하나(무작위)이고, 색은 지금처럼 `DAN_COLORS`. 몸 색 단의 문제가 조금 더 자주 나온다.
- 지도 데이터는 코드 안 2차원 배열(`src/field/maps/meadow.ts`·`waterside.ts`·`desert.ts`).

### 4-2. 이동
- 칸 단위 이동(한 칸 걷는 데 약 180ms, 그동안 부드럽게 옮겨 그림). 누르고 있으면 계속 걷는다.
- 방향 바꾸기만: 짧게 톡 누르면 그 방향을 보기만 한다(원작 손맛).
- 카메라는 캐릭터를 가운데에 두고 지도 끝에서 멈춘다.
- 키보드(방향키·WASD·Z/X)도 같은 입력으로 받는다(개발·태블릿용).

### 4-3. 만남
- 풀숲 칸에 **들어설 때마다 12%** (상수 `ENCOUNTER_CHANCE`). 전투가 끝나고 **3걸음 안에는 만나지 않음**(`ENCOUNTER_GRACE_STEPS`).
- 만날 구구몬은 **그 필드의 몬스터**(4-1 표)에서 무게를 달아 고른다. 도감에 없는 종이 조금 더 잘 나온다(모으는 재미).
- 야생 레벨: 필드와 상관없이 Lv 3~6.
- **레전드 구구몬 (확정)**: 어느 필드든 풀숲 만남마다 **2%** (`LEGEND_CHANCE`)로 나타난다(글로벌 랜덤). 자세한 규칙은 6-4.

### 4-6. 필드마다 따로 불러오기 (확정)
- 필드마다 지도·타일 그림(나중엔 그 필드 몬스터 스프라이트도)을 **따로 묶어** 그 필드에 들어갈 때 불러온다(`import()`로 나눠 빌드 → 처음 앱을 켤 때 무겁지 않게). 테스트판 몬스터 그림은 지금 앱에 이미 들어 있는 SVG라 따로 불러올 것이 없다.
- 불러오기 화면: 필드 이름과 세 단(예: "물가 · 3·6·9단"), 그 필드 몬스터 실루엣, 짧은 구구단 한 줄(예: "6 × 7 = 42 기억나?"). 불러오기가 빨리 끝나도 **최소 0.6초**는 보여 줘 화면이 번쩍이지 않게.
- 한 번 받은 필드는 서비스 워커가 저장해 두어 오프라인에서도 열린다(지금 PWA 설정이 빌드 파일을 모두 캐시하므로 따로 할 일은 확인뿐).
- 불러오기에 실패하면(오프라인 + 아직 안 받은 필드) "인터넷에 연결되면 갈 수 있어요" 안내 후 지금 필드에 그대로 둔다.

### 4-4. 터치패드
- 왼쪽 아래 **십자 패드**(지름 약 140px). 손가락을 올린 채 미끄러뜨리면 방향이 바뀐다(가운데에서 가장 가까운 방향 4개 중 하나, 가운데 작은 원 안은 멈춤).
- 오른쪽 **A**(표지판 읽기·확인), **B**(취소). **달리기는 없다 (확정).**
- `pointerdown/move/up` + `setPointerCapture`로 처리, 화면이 스크롤·확대되지 않게 `touch-action: none`.
- 멀티터치: 십자 패드와 A 버튼을 동시에 눌러도 따로 처리(pointerId별).

### 4-5. 그리기 방식
- 필드는 **canvas 1장**(지도+캐릭터)에 그리고, 메뉴·터치패드는 React로 위에 얹는다.
- 그림은 이미지 파일이 아니라 **코드 픽셀 배열**(지금 SVG 그림처럼 우리가 직접 만든 것)로 두고, 처음 한 번 오프스크린 canvas에 구워서 쓴다.
- 방금 설치한 `pixelfx`(MIT 라이선스)로 전환 효과(transitions)·타격(impacts)·포획(spawn & death, pickups) 효과를 쓴다. 쓰는 효과는 `NOTICE`에 적는다.

## 5. 야생 전투

### 5-1. 시작
1. 필드 → 전환 효과(약 0.8초) → 전투 화면
2. "야생 ○○몬이 나타났다!" 한 줄(탭하면 넘김, 1.2초 뒤 자동)
3. 첫 문제가 뜬 순간부터 시간이 흐른다.

### 5-2. 문제와 버튼
- 야생 구구몬 말풍선에 문제: "7 × 8 = ?"
- 아래 버튼 3개: **[기술 이름] [보기 숫자]** 예) `잎사귀 톡 · 56`
  - 기술 이름은 **내 동행 구구몬의 기술 3개**(종마다 3개 지정). 보기 숫자 위치는 문제마다 섞이고, 기술 이름은 늘 같은 자리(손에 익게).
- 정답 → 내 구구몬이 그 기술을 쓰는 연출(약 0.6초, pixelfx 효과) → 야생 HP가 줄고 → 다음 문제.
- 오답 → 기술이 빗나감, 야생 HP는 그대로. 지금처럼 **힌트 패널**을 보여 주고 같은 사실을 나중에 다시 낸다(`insertRetry`). 힌트를 보는 동안에는 **시간이 멈춘다**(HP 회복·도망 타이머 모두).
- 연출 중에도 시간은 멈춘다. **시간은 "문제가 떠 있고 아이가 답을 고를 수 있는 동안"에만 흐른다.**

### 5-3. HP 규칙 (수치는 상수로 두고 테스트로 고정)
| 이름 | 추천값 | 뜻 |
|---|---|---|
| `WILD_MAX_HP` | 100 | 야생 최대 HP |
| `HIT_DAMAGE` | 40 | 정답 1번에 깎는 양 |
| `FAST_HIT_BONUS` | +10 | 빠른 정답(`fastThresholdMs` 안)이면 더 깎음 |
| `REGEN_PER_SEC` | 3 | 1초에 차오르는 양 (꽉 차 있지 않을 때만) |
| `FLEE_AFTER_FULL_MS` | 아래 표 | HP가 꽉 찬 채 이만큼 지나면 도망 |

회복이 깎는 양을 따라잡지 못하게 맞춘 값이다. 아래 계산은 "문제 하나 푸는 데 걸린 시간 동안 차오른 양"을 뺀 실제로 줄어드는 양이다.

| 아이 | 한 문제에 걸린 시간 | 1번 맞힐 때 실제로 줄어드는 양 | 쓰러뜨리기까지 |
|---|---|---|---|
| 빠름 | 3초 (빠른 정답) | 50 − 9 = 41 | 3번 |
| 보통 | 5초 | 40 − 15 = 25 | 4번 |
| 느림 | 8초 | 40 − 24 = 16 | 6~7번 |

- 느린 아이도 반드시 이길 수 있어야 한다: **테스트로 "한 문제에 10초씩 걸려도 `WILD_MAX_QUESTIONS` 안에 쓰러진다"를 고정**한다(40 − 30 = 10 → 10번).
- 오답은 HP를 깎지 않지만 힌트를 보는 동안 시간이 멈추므로, 틀렸다고 야생이 회복하지는 않는다.

- **도망 시간은 지금 떠 있는 문제의 난이도에 따라 정한다 (확정)**. 전투 시작 때 HP가 꽉 차 있으므로 첫 문제에 특히 중요하다.
  | 지금 문제 | 기본 시간 |
  |---|---|
  | 2·3·4·5단 | 7초 |
  | 6·7·8·9단 | 9초 |
  | 12단 · 13단(레전드) | 12초 |
  | 아직 잘 모르는 문제(숙련도 상자 0~1)라면 | 위 시간 **+3초** |
  | 빈칸 문제(□×4=12)라면 | 위 시간 **+2초** |
  예) 7×8=? 을 처음 만나면 9+3 = 12초, 익숙한 3×4=? 는 7초.
- 관리자 화면에서 전체를 느리게·보통·빠르게(×1.5 / ×1 / ×0.8) 바꿀 수 있게 한다.
- HP 바가 꽉 차면 **바 테두리가 깜빡이고 작은 모래시계가 줄어드는 표시**로 도망 시간을 보여 준다.
- 내 구구몬은 HP가 없다. **아이가 지는 일은 없다**(지금 앱의 "실패 상태 없음" 원칙). 최악은 "도망갔다"뿐.
- 한 전투 최대 문제 수 `WILD_MAX_QUESTIONS = 12` (위 '느림' 계산의 10번보다 여유 있게). 넘으면 야생이 "지쳐서 잠들었다" → 캡슐 던지기로 넘어감(지금 `MAX_ATTEMPTS` 잠들기 규칙과 같은 생각, 끝없이 끌리지 않게).

### 5-4. 캡슐 던지기
- HP가 0이 되면 야생이 **어지러운 상태**: HP 회복 멈춤, 버튼 3개가 **[캡슐 던지기] 하나**로 바뀐다.
- 성공 확률 **30%** (`CATCH_CHANCE`). 흔들림 3번 연출 뒤 결과.
- 실패하면 (확정):
  - 캡슐에서 튀어나와 **HP 40%로 회복**, 회복·도망 타이머 다시 시작 → 다시 맞혀서 쓰러뜨리면 또 던질 수 있다.
  - **실패할수록 성공 확률 +15%** (30 → 45 → 60 → 75 → 90 → 100) — 어린이가 연달아 놓쳐 속상하지 않게. 쓰러뜨릴 때마다 문제를 더 풀게 되니 학습에도 좋다. 확률은 그 전투 안에서만 오르고 다음 전투는 30%부터.
- 캡슐 수: **무제한 (확정)**. 개수 표시도 없다.

### 5-5. 전투 끝
| 결과 | 보상 |
|---|---|
| 잡음 (새 종) | 도감 등록, "새로 만났어!" 연출 |
| 잡음 (이미 있는 종) | 그 종의 경험치 + `DUPLICATE_EXP` |
| 도망감 | "○○몬이 도망갔다…" — 맞힌 문제 보상은 그대로 받음 |
| 그만두기(B 버튼 → 확인) | 도망과 같음 |

- 모든 경우 **동행 구구몬 경험치 + 참여 경험치**, 정답마다 별·펫 친밀도(지금 규칙 그대로).
- 답 하나하나는 바로 `recordAnswer`로 저장(전투 중 앱을 닫아도 학습 기록은 남는다).

## 6. 구구몬 · 경험치 · 진화

### 6-1. 종
#### 테스트판 (확정): 지금 있는 몬스터 8종만, 새로 그리지 않는다
- 종 = 지금 `MonsterKind` 8종. 그림은 지금 `MonsterSprite`(SVG) 그대로 쓴다 — 단 색으로 칠하기, 황금 모습, 표정(`idle`·`hit`·`happy`·`sleep`)이 이미 있다.
  | 필드 | 몬스터 (`kind`) | 기술 3개 (임시) |
  |---|---|---|
  | 초원 | 새싹몬 (`cloud`) | 잎사귀 톡 · 새싹 휙 · 꽃잎 바람 |
  | 초원 | 방울무몬 (`mushroom`) | 방울 딸랑 · 데굴데굴 · 무 박치기 |
  | 초원 | 왕관몬 (`fluff`) | 왕관 반짝 · 꼬리 흔들기 · 몸통 박치기 |
  | 물가 | 젤리몬 (`jelly`) | 젤리 톡 · 출렁 박치기 · 거품 뿜기 |
  | 물가 | 안테나몬 (`antenna`) | 안테나 찌릿 · 신호 빔 · 빙글 돌기 |
  | 물가 | 뿔뿔몬 (`horn`) | 뿔 콕 · 돌진 · 물결 치기 |
  | 사막 | 삼눈블록몬 (`pebble`) | 블록 쾅 · 세눈 빔 · 단단해지기 |
  | 사막 | 외뿔공룡몬 (`ghost`) | 외뿔 찌르기 · 꼬리 휘두르기 · 공룡 함성 |
- 같은 종이라도 만날 때마다 몸 색(단)이 다를 수 있다. **도감은 종(8칸)으로 센다** — 색이 달라도 같은 종.
- 내 동행의 뒷모습 그림이 없으므로, 전투에서 내 몬스터는 **같은 그림을 좌우로 뒤집어 왼쪽 아래에 조금 작게** 놓는다.
- 필드에서 따라 걷는 동행은 SVG를 작은 그림으로 한 번 구워(canvas `drawImage`) 쓴다.
- 첫 구구몬 고르기: **새싹몬(초원)·젤리몬(물가)·삼눈블록몬(사막)** 중 하나.
- 속성·상성은 테스트판에서 넣지 않는다(문제를 맞히면 늘 같은 양을 깎는다).

#### 정식판: 테스트판을 통과한 뒤 스프라이트로 바꾸기
- 그림을 고르는 곳을 **한 군데**로 모은다: `creatureSprite(kind, { stage, view: 'front' | 'back' | 'mini', mood, golden, color })`. 테스트판은 여기서 `MonsterSprite`를 돌려주고, 정식판은 이 함수 안만 바꿔 스프라이트 이미지를 돌려준다. 전투·도감·필드 화면은 고치지 않아도 된다.
- 스프라이트를 들일 때 정할 것: 한 칸 크기(예: 64×64), 앞·뒤·작은 그림, 진화 단계별 그림, 맞을 때 등 표정이 따로 있는지, 필드마다 따로 불러올 묶음(4-6).
- 가져오는 스프라이트는 **쓸 권리가 있는 것**이어야 한다(직접 그린 것, 또는 상업·공개 사용이 허락된 라이선스). 원작 게임 그림을 뽑아 온 것은 공개 주소에 올릴 수 없다(0절).
- **PMD SpriteCollab 검토 결과 (2026-11-03): 쓰지 않는다.**
  - 저장소 그림은 CC BY-NC 4.0이다(그린 사람 이름 표시, 비상업만). 이 조건 자체는 무료 앱이라 맞출 수 있다.
  - 하지만 그림 속 캐릭터가 **포켓몬**이다. 팬 작가가 준 라이선스는 "그린 그림"에만 미치고, 포켓몬 캐릭터 권리(닌텐도·게임프리크·크리처스·포켓몬컴퍼니)는 줄 수 없다.
  - 저장소에는 원작 게임(춘소프트)의 공식 그림도 함께 들어 있다.
  - 공개 GitHub 저장소·Pages에 올리면 권리자의 삭제 요청 대상이 될 수 있고, 그때는 퀴즈 모험까지 같은 저장소째 내려갈 수 있다.
  - 대신 쓸 수 있는 것: 직접 그린 픽셀 몬스터, CC0·CC BY 라이선스의 **창작 몬스터** 묶음(OpenGameArt·itch.io 등, 남의 게임 캐릭터가 아닌 것), 그림 의뢰.

### 6-2. 레벨과 경험치 (추천값)
| 이름 | 값 |
|---|---|
| 레벨 범위 | 1 ~ 30 |
| 다음 레벨에 필요한 경험치 | `20 + 레벨 × 10` (Lv1→2: 30, Lv10→11: 120) |
| 같은 종을 또 잡음 | +40 |
| 전투 참여(동행) | +10, 그 전투에서 맞힌 문제마다 +2 |
| 진화 | 1→2단계 **Lv8**, 2→3단계 **Lv18** |

- 경험치는 **종마다 하나**. 같은 종을 여러 번 잡아도 도감엔 한 칸, 대신 경험치·"잡은 횟수"가 오른다.
- 야생은 늘 1단계 모습으로 나온다. 이미 진화시킨 종을 또 잡아도 그 종의 경험치로 들어간다.
- 레벨업·진화 알림은 지금 펫처럼 `useSessionStore`에 대기열로 넣고 전투 결과 뒤에 보여 준다.
- **테스트판의 진화 모습**: 진화형 그림이 없으므로 같은 그림을 **조금 더 크게**(1단계 1 → 2단계 1.15 → 3단계 1.3배) 그리고 이름 앞에 단계 표시(예: "젤리몬 ★★")를 붙인다. 진화 규칙(레벨·알림)은 정식판과 똑같이 동작하게 만들어 두고 그림만 나중에 바꾼다.

### 6-3. 도감 · 동행
- 도감 칸: 아직 못 만남(실루엣 ?), 만났지만 못 잡음(흑백), 잡음(색·레벨·잡은 횟수).
  - "만남"도 기록한다(어디에 나오는지 아이가 알 수 있게).
- 잡은 구구몬을 누르면 **[함께 다니기]** → 동행이 된다. 필드에서 캐릭터 뒤를 따라 걷고, 전투에 나간다.
- 동행은 1마리.
- 도감은 필드별 묶음(초원 3·물가 3·사막 2) + **레전드** 칸 3개 = 테스트판 11칸.

### 6-4. 레전드 구구몬 (확정: 13단, 어디서나 드물게)
- **3종**. 진화하지 않는다.
  - 테스트판: 새 그림 없이 지금 몬스터의 **황금 모습**(`golden`)을 쓴다 — **황금 왕관몬·황금 뿔뿔몬·황금 외뿔공룡몬**(필드마다 하나씩). 일반 종과 도감 칸은 따로. ⚠️ 추천안
  - 정식판: 레전드 스프라이트로 바꾼다.
- 나타나는 곳: 세 필드 어디든 풀숲 만남마다 2%.
- 나타나는 조건: **퀴즈 모험에서 12·13단이 열린 뒤**. 그 전에는 나오지 않는다(13단 문제를 아직 낼 수 없으므로).
- 문제: **13단만**(곱셈·빈칸). 13단 안에서는 출제 엔진이 약한 문제를 고른다.
- 도망 시간: 13단 기본 12초(+숙련도·빈칸 가산은 같음).
- 등장 연출: 화면이 반짝이는 특별 전환, "전설의 ○○몬이 나타났다!"
- HP·캡슐 규칙은 일반 구구몬과 같다(30%, 실패마다 +15%). 다시 잡으면 경험치(레벨만 오름).
- 레벨: 등장 레벨 20 고정.

## 7. 저장 데이터

`SaveData`에 `field` 하나를 더한다. CLAUDE.md 규칙대로 **네 곳**(`createInitialSave`, `mergeSave`, `partialize`, `DataSecurityPanels.currentSave`)을 함께 고치고 저장 형식 버전을 올린다.

```ts
interface FieldData {
  starterChosen: boolean;
  companion: SpeciesId | null;       // 동행
  // SpeciesId = MonsterKind(8종) | 'legend-fluff' | 'legend-horn' | 'legend-ghost'
  // 정식판에서 스프라이트를 바꿔도 이 아이디는 그대로 둔다 → 저장 데이터를 고칠 필요가 없다
  species: Partial<Record<SpeciesId, {   // 잡은 종
    level: number; exp: number;
    stage: 1 | 2 | 3;                // 진화 단계
    caught: number;                  // 잡은 횟수
    firstCaughtAt: number;
  }>>;
  seen: SpeciesId[];                 // 만났지만 못 잡은 것 포함
  position: { map: 'meadow' | 'waterside' | 'desert'; x: number; y: number; facing: Dir };
  stats: { battles: number; catches: number; fled: number };
}
```

- 전투 중 상태(HP·타이머)는 저장하지 않는다(`useSessionStore`). 앱을 다시 열면 필드의 마지막 자리에서 시작.
- `pwa/autoUpdate.ts`의 `BUSY_ROUTES`에 전투 화면 주소를 넣어, 전투 중 새 버전 자동 새로고침이 일어나지 않게 한다. 필드 화면은 자동 새로고침해도 자리가 저장돼 있으니 괜찮다.

## 9. 테스트

- 단위(Vitest): 회복·도망 타이머(힌트·연출 중 멈춤 포함), 캡슐 확률(난수 고정), 실패 시 확률 오름, 경험치·레벨·진화 경계값, 만남 확률·안전 걸음, 칸 이동 충돌, 3지선다 보기에 정답이 꼭 하나, 필드 정답의 상자 상한, `mergeSave`가 옛 저장에 `field` 기본값을 채우는지, 필드마다 그 필드 몬스터만 나오는지, **필드 문제가 그 필드의 세 단에서만 나오는지**(오답 복습 슬롯은 예외), 12·13단이 닫혀 있으면 레전드·12단 문제가 나오지 않는지, 퀴즈 모험의 출제는 단 목록 변경 뒤에도 그대로인지, 레전드 전투는 13단 문제만 내는지, 난이도별 도망 시간 표.
- 지도 검사: 필드마다 입구에서 모든 풀숲·출구로 걸어갈 수 있는지(막힌 곳에 갇히지 않는지) 자동으로 확인.
- E2E(Playwright): 첫 구구몬 고르기 → 풀숲에서 만남(테스트에선 만남 확률 100%로) → 3문제 맞힘 → 캡슐(확률 100%로) → 도감에 보임 → 동행 바꾸기. 터치패드는 휴대폰 크기 화면에서 포인터로 누르기.
- 화면 확인: 개발 서버에서 375px로 직접 걸어 보고 전투해 보기.

## 10. 만드는 순서 (단계마다 배포 가능하게)

| 단계 | 내용 | 끝났다는 기준 |
|---|---|---|
| M0 | 타이틀 화면(퀴즈 모험 = 지금 앱 그대로) + 필드 뼈대: 초원 지도 1장, 칸 이동, 터치패드, 충돌 (그림은 임시 색 칸) | 타이틀에서 두 모험으로 들어가고, 초원을 휴대폰에서 걸어 다닐 수 있다. 퀴즈 모험의 기존 E2E가 모두 통과 |
| M1 | 야생 전투 핵심: 만남 → 전투, 보기 3개, HP 회복·도망, 기존 출제·답 기록 연결 | 문제를 풀면 학습 기록이 지금처럼 쌓인다 |
| M2 | 캡슐·도감·첫 구구몬 고르기, 저장 데이터 `field` | 잡은 구구몬이 도감에 남고 다시 켜도 그대로 |
| M3 | 물가·사막 필드 + 따로 불러오기 + 필드별 단·몬스터 + 레전드(황금 모습) | 세 필드를 오가며 그 필드 몬스터·단만 만나고, 12·13단이 열리면 레전드가 가끔 나온다 |
| M4 | 경험치·레벨·진화(크기·★ 표시), 동행 바꾸기, 따라 걷기 | 같은 종을 잡거나 전투하면 레벨이 오르고 Lv8에 진화 |
| M5 | 필드 타일·주인공 그림, pixelfx 효과, 타이틀 그림, 관리자 설정(도망 시간 등) | **테스트판 완성**: 375px에서 처음부터 끝까지 놀 수 있다. 몬스터는 기존 8종 그림 |
| M6 | 테스트판 써 보기 → 고칠 점 반영, 설계서 v1.34 기록, 배포 | 라이브에서 동작 |
| M7 | **(뒤로 미룸)** 캐릭터 개발 — 그림 출처를 정한 뒤 몬스터 스프라이트 들이기: `creatureSprite` 안만 바꾸기, 진화형·뒷모습·레전드 그림 | 화면 코드와 저장 데이터를 고치지 않고 그림만 바뀐다 |
